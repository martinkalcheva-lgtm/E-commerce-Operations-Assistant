## Alembic 1049 Unknown database 排查（只读，未改动）

- 现象：`alembic revision --autogenerate` 报 `(1049, "Unknown database 'ecommerce_operation'")`
- 根因：**连错容器**。api/.env 的 DATABASE_URL 指向 127.0.0.1:3306，但宿主机 3306 被 `mysql-demo`（无关测试容器，root 密码恰好同为 123321）占用；项目 compose 的 `mysql-1` 容器正常初始化、里面**有** ecommerce_operation 库，但创建时没带宿主机端口映射（docker ps 只显示 `3306/tcp`，无 `0.0.0.0:xxxx->3306`）。
- 次要发现：项目根**没有 .env**，而 docker-compose.yml 用 `${MYSQL_ROOT_PASSWORD:?}` 强制校验，直接 `docker compose up` 会报错；重建容器前必须先补根 .env。
- 修复方案已给用户（待确认）：① 建根 .env（root 密码 123321 与 api/.env 一致）；② 端口二选一——停掉 mysql-demo 让项目用 3306，或 MYSQL_PORT=3307 并同步改 api/.env；③ `docker compose up -d` 重建（named volume mysql-data 保数据不丢）；④ 重跑 alembic。
- 环境坑：本机 WorkBuddy 的 bash shim PATH 损坏（cat/ls/grep/head/sleep/(dirname) 均不可用），docker 需用完整路径 `C:\Program Files\Docker\Docker\resources\bin\docker.exe`，且命令输出需重定向到文件后用 Read 读取；PowerShell 工具输出捕获亦失效。
- **纠正**：项目根 `.env` 实际**存在**（上一轮 Test-Path 因 shell 故障误报缺失），密码 123321、库名 ecommerce_operation 均已配好，无需新建。

## 修复完成（已执行）

1. `docker stop + rm mysql-demo`（无关测试容器，占着宿主机 3306）→ 释放端口
2. `docker stop ecommerce-redis-demo ecommerce-postgres-demo`（两个空壳 demo，占 6379/5433）
3. `docker compose up -d --force-recreate`（**关键**：首次 `up -d` 只重启旧容器、不补端口映射；必须 `--force-recreate` 才会照新配置重建）
4. 结果：mysql-1 → `127.0.0.1:3306->3306`，redis-1 → `6379`，agent-checkpoints-1 → `5433`，均 healthy
5. 验证：宿主机 pymysql 连通 `ecommerce_operation` 库成功。数据在 named volume `ecommerce-operation-assistant_mysql-data` 中，未丢。
- 经验：`docker compose up -d` 对「配置变更但容器已存在」不会自动重建；端口映射等结构性变更必须加 `--force-recreate`。
- 待用户执行：`uv run alembic revision --autogenerate -m "initial final schema"`
