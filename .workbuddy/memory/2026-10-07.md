## 生成任务队列机制（重要，跨会话复用）
- `generation_jobs` 即任务队列。状态流转：pending → running → succeeded / failed / cancelled。
- **进度看每条 job 的 `events` 数组**：queued → started → succeeded / failed（另有 retry_scheduled / cancelled / timeout_checked）。
- **只有两个消费者**：① API 在调生成接口时用 FastAPI background task 派发一次；② 独立调度器 `app.worker.generation_scheduler`（每 5s 扫 DB，重新派发到期 pending，含重试/漏投递）。**API 自身不扫队列**（全仓库确认 `dispatch_due_generation_jobs` 只存在于 worker 文件）。
- 配置：`api/.env` 中 `TASK_QUEUE_BACKEND=inline`（非 celery，无需 broker worker）。
- 前端/查看进度：`GET /products/{id}` 返回体里 `generation_jobs[].events`。
- `/workspace/generation-jobs/sweep-timeouts` 目前是空壳，返回 501。
- 任务卡在 pending 的判据：`attempts=0` + `locked_by=null` + 只有 1 条 queued 事件 = 没有任何消费者领取。

## 反复出现的 `uv` os error 5 —— 根因定位（重要）
- 现象：`uv run` 报 `failed to remove file ...\sqlalchemy\....pyd: 拒绝访问 (os error 5)`；每次锁的文件不同；最终 sqlalchemy 损坏（`__file__=None`、`create_engine` 导入失败、`sqlalchemy-2.1.1.dist-info` 缺 RECORD）。
- 根因：锁文件要求 `sqlalchemy==2.0.52`，但环境里残留 `2.1.1`。uv 每次自动同步都要删掉 2.1.1 做降级，而 **正在运行的 API 服务（uvicorn，监听 127.0.0.1:8000）加载了 sqlalchemy 的 `.pyd` C 扩展，锁死文件** → 只删一半 → 包损坏 → 下次再撞 → 死循环。
- 修复步骤：停掉 API 服务相关全部 python 进程 + 残留 `uv.exe` → `uv sync --reinstall-package sqlalchemy` → 验证 `create_engine` 可导入。本次已修复，sqlalchemy 回到 2.0.52。
- **教训（必守）**：跑 `uv sync` / `uv add` / `uv run`（会触发环境同步）之前，先停掉正在运行的 API 服务，否则必撞文件锁。

## "生成图片/视频很慢"的真实根因（重要，实测数据）
- **不是慢，是被服务端拒绝**：job#2（图片）`started` 后 **1 秒内**就 `retry_scheduled`，错误体 `{'code': 50400, 'data': None, 'message': 'Access Denied', 'request_id': ...}` —— 火山引擎视觉智能直接拒绝（即梦 `jimeng_t2i_v30`）。
- **三层"看起来慢"的叠加**：
  1. **失败退避**：`generation_jobs._mark_failed_or_retry` → `next_run_at = now + min(attempts*2, 10) 分钟`，`max_attempts=3` → 最坏 2+4=6 分钟后才转 failed；这期间状态是 pending/running，界面一直在"生成中"。
  2. **轮询上限被配大**（`api/.env` 比代码默认大得多）：`IMAGE_POLL_INTERVAL_SECONDS=5 × IMAGE_POLL_MAX_ATTEMPTS=60 = 300s`；`VIDEO 10 × 90 = 900s`（代码默认仅 24/36）。真跑通时界面也会等很久。
  3. **inline 模式调度是串行的**：`generation_scheduler`（5s 扫一次、BATCH_SIZE=20）对每条 job 直接**同步执行**（`dispatch_generation_job` 无 background_tasks 时 `run_generation_job(job_id)`），一条跑完才下一条；**未启动 scheduler 时，非 API-background 路径的任务会永远 pending**（证据：job#1 从 03:23:47 pending 到 07:50:24 被取消，4.5 小时无人消费）。
